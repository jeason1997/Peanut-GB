# 屏外显示：实验结果、架构与移植手册

## 0. 整理后的源码位置

主工程恢复上游基线；仅新增 extensions/。不把测试接线或SDL实验长期写入原核心/examples/test。
下文提及的旧SDL viewport API、examples/common兼容头及 test/test_silver_jp 等文件，在应用可选接入/回归Patch后才存在；它们的源码差异归档于本目录 patches/0002 和 0003。
独立模块 tests/ 使用原版核心公共回调，可在不应用这些Patch时运行。

## 1. 必须保留的语义

扩展区域是额外展示，不是新增硬件扫描线。GB 仍按 160×144、原 LY/模式/中断节奏执行；NES 也必须保留其真实 PPU 时钟、vblank、sprite hit/overflow、mapper IRQ 行为。
原生帧与扩展合成帧必须区分：原生帧用于模拟精确性验证，合成帧允许增加游戏可见内容。
不要为了输出 150 行而使 GB PPU 真正执行 150 条可见扫描线。

“补丁”有两种：

1. **源代码接入 Patch**：可审阅、应用/回退的 diff，修改某个模拟器的接线；不是游戏 ROM。
2. **运行时游戏读取 Patch**：CPU 读指定 ROM 地址时替换返回值；磁盘 ROM 不变，但游戏执行路径、NPC AI 数量与 RNG 消耗可以改变。

现有《银》属于二者结合；宣称“完全没有改游戏逻辑”是不准确的。运行时补丁不改变指令长度或指令的硬件计时规则，不代表执行的分支/指令总量不变。

## 2. 为什么无法凭同一个算法支持所有游戏

PPU 只知道 tile、属性、OAM、滚动位置。屏外 tilemap 可能是缓存、旧地图、环形缓冲或即将替换的列，OAM 通常只保存当前可见对象。
《银》的完整地图由 ROM 元图块、WRAM 地图窗口、连接表和对象表共同决定；其他游戏可能用压缩地图、脚本生成、不同 bank、分屏卷轴。
因此三层解耦：

```text
前端/面板输出 ← 通用合成器 ← 通用 PPU 背景 或 游戏后端
                                  ↑
                        模拟器只读状态/ROM 数据源
CPU 读 ROM ← 可选、精确版本匹配的游戏读取补丁
```

通用 fallback 应标注为 VRAM 扩展，不能把过期屏外 tile 当成正确地图。
下一款游戏应新增后端，而不是往通用合成器里追加游戏名/地址判断。

## 3. 通用合成接口

`gx_viewport_init` 接收原始宽高、目标宽高、一条调用方缓冲、回调和背景/前景位；无 malloc、SDL 或系统 API。
目标尺寸是 uint16，必须大于等于原尺寸；超出行缓冲容量拒绝初始化。调用者必须保证每个内存视图的实际长度与文档一致。
`gx_viewport_begin` 开始一个展示帧；`gx_viewport_push(y, pixels, count)` 接收按序完整原始行。函数复制输入后再做可选前景，原始输入不变。
上下边距用首末原始行附近的后端状态绘制，左右边距逐行绘制，中心区域不会被背景重复绘制。
背景回调收到的内存已填 blank；后端无效时可以直接返回。`emit` 必须当场消费/复制行，行缓冲下次调用即复用，不能把裸指针异步交给 DMA 后立即覆盖。

`begin` 回调应在原生第一条真实可见行到达时采集游戏快照，不要在 CPU 尚未执行这一帧之前采集。
推荐在原 LCD 回调 `y==0` 时调用 `gx_viewport_begin`，其余调用 push。游戏开关 LCD 时可能先输出不完整帧；丢弃直到下一条 y=0。push 对缺失/重复行返回 0，前端应终止这个展示帧并等待新帧。
逐行中途已经 emit 的部分无法回滚；需要原子提交的前端请在完整帧缓冲中合成，再提交面板。
跳帧/隔行输出必须由移植层明确处理：提供完整帧，或沿用原有跳帧输出策略；不得把不完整行集伪装成完整帧。

GB 用 160×144；FC 测试用了 256×240。合成器本身没有写死 160，但《银》后端当然写死对应硬件/游戏布局。

## 4. 接入其他 GB 模拟器

### 4.1 状态视图

`gx_gb_view` 只借用指针，不复制内存：WRAM C000-DFFF 共 8192 字节、VRAM 8000-9FFF 共 8192 字节、OAM 160 字节、FF00-FFFF 共 256 字节。
最后一个视图包含 I/O+HRAM+IE，不能只提供 FF80-FFFE；如宿主分开保存，应由桥接层构建/更新这个 256B 小快照。
提供当前 CPU PC/BC、解码后的 BG[4]/OBJ[8] 灰阶映射；PC 必须符合补丁比较使用的“当前取数后”语义。其他模拟器 PC 时点不同必须调整端口，不要照搬地址判定。
CGB 模式的银行/调色板不在此接口的承诺中；本后端针对 ROM 的 DMG 兼容运行方式。

不要强转其他模拟器的 context 为 gb_s。使用状态视图，或在性能敏感端口通过 `PGB_SILVER_STATE` 实例化兼容布局访问；这只是接线优化，游戏算法仍在独立头文件。
一个翻译单元只选择一种实例化方式，不要同时包含旧 Peanut 兼容头与默认中立实例；多种宿主并存时分开 TU。

### 4.2 最少调用顺序

1. 初始化适配器并验证 ROM 指纹；设置尺寸与 features/object_limit。
2. 初始化合成器与宿主状态视图，注册原始 LCD 行回调。
3. 第一条原始行：更新视图，begin → `pgb_silver_begin_frame`。
4. 背景跨度：刷新实际扫描行相关的寄存器/调色板视图，调用 background；无效场景留 blank。
5. 中心前景：刷新视图，调用 foreground；只为邻图预览与原屏边界衔接使用，原生玩家/当前 NPC 的不透明像素优先。
6. 若启用游戏逻辑补丁，在 **所有可能读取补丁字节的数据/指令路径** 中调用 rom_read；不能只修改普通 mapper 回调却让快速取指绕过。
7. reset/加载状态/切换 ROM 时重新初始化适配器，清除上一游戏的快照、图谱、对象历史。

完整示例：`tests/test_portable_silver.c`。该路径不需要 Peanut 核心的 viewport API，证明游戏后端与通用合成可以经前端接入。
现有 SDL 保留旧 viewport API，作为性能/兼容路径；其核心改动单独作为可选 Patch 分发，不要求其他模拟器照搬。

### 4.3 ROM 数据访问的现实限制

当前《银》后端仍要求可连续寻址的只读 1MiB ROM 指针。数据访问已移出模拟器核心，但 **尚未抽象成 SD 分页读取服务**。
不能把 SD 缓存某一页的地址当成整份 ROM 基址；不能缓存指向会被驱逐页的长寿命指针。
面向 AC6956C8 的下一步应增加受控 ROM span/read 接口，把频繁访问的事件、连接、精灵图形元数据复制到有上限的小缓存；测缺页与字节数，再决定批量预取。
不要为了“通用化”给每次 CPU 取指再套一层昂贵回调；CPU 快路径与展示数据读取路径应分开。

## 5. 《银》Rev 1 已验证的数据与算法

精确指纹：1,048,576 字节；SHA1 `a11d5ddc26eb826086593f82370b15d16404d33e`；CRC32 `0aea5383`。代码初始化校验长度+CRC32。
参考反汇编为 Narishma-gb/pokesilver 提交 `edbe53978ef1777fc5c41019e17b7544070eab92`，不作为运行/构建依赖。
这些地址只适用于该版本，不能直接套给英文银、金、红。

|用途|CPU 地址或 ROM 物理偏移|关键细节|
|---|---|---|
|地图状态|D14B|2 为活动；1 可是连接地图装载过渡|
|战斗状态|D108|非零时不扩展地图|
|地图 padded blocks|C700，最多1300字节|四周各3个32px block；不能把 padding 当真实世界|
|尺寸|D079/D07A|高度/宽度加6得到 padded 维度|
|定义|D0B7 bank，D0B8 pointer|一个32×32 block=16个8×8 tiles；原游戏 ID 有7位回绕|
|地图原点/锚|D06F、D071/D072、D04D|需与实际 SCX/SCY 对齐|
|直接连接|D083 flags，D084+side×12|北南西东，过滤不兼容 tileset|
|MapGroupPointers|ROM 0x940ed|组1..26，9字节 map header|
|当前地图/玩家位置|D9C6/D9C7，D9C8/D9C9|group/number、Y/X|
|活动对象|D1F0，13槽，每槽40B|包含玩家；8位 sprite 坐标需要解包为地图坐标|
|当前地图对象记录|D438，16槽，每槽16B|真实事件对象从 index2 开始|
|隐藏掩码/变量精灵|D538 / D548|不能盲画被事件隐藏的对象|
|事件标志|D7AA|读取事件可见性，不写标志|
|当前小时|FF96|日版实测；参考符号 HRAM 有偏移，不可盲信|
|方向姿态表|ROM 0x404a，数据0x408c..0x4273|拼图、透明、翻转、优先级|
|精灵描述|ROM 0x147b0|不可依赖已被游戏复用的 VRAM 旧槽|

地图块按 ROM 真实地图矩形确定空间归属；非地图区域选距离最近的矩形及其 border，同距按稳定地图 ID 决定。缓存整个同 tileset 连通分量并在换图时整体平移，避免水/树随当前地图变化而整屏刷新。
当前算法对某些其他连通分量发现过连接嵌入冲突，尚未实现通用冲突解决；新地图区域须单独验证。

相邻 NPC 根据事件记录、时间、事件标志，以及有上限的对象回调解释判断可见性。只理解已列明的回调指令，未知操作/循环/无法确定变量时保守跳过该地图预览。不会执行游戏脚本或修改 RNG/RTC。
邻图预览是初始位置/姿态，不运行邻图 AI；切图后真实对象接管。离开地图后预览可能回到 ROM 初始位置，不是跨地图永久 NPC 状态模拟。
变量精灵无法确定时跳过，不猜测。物体/玩家遮挡由原始像素层标签处理；无标签时回读 OAM 覆盖，可能更贵。

### 5.1 运行时 ROM 读取替换

|物理偏移|效果|
|---|---|
|0x9675a|边缘扫描改用已有完整窗口初始化入口|
|0x4397 / 43c3 / 878d|X 激活范围扩围|
|0x439c / 43c8 / 8792|X 比较范围扩围|
|0x43a9 / 43d5 / 879b|Y 激活范围扩围|
|0x43ae / 43da / 87a0|Y 比较范围扩围|
|0x592f，PC=5930，BC对象槽校验|避免远处对象以8位坐标绕回原屏另一侧|
|0x4275+movement×6，PC=18d1|同一对象重载时恢复朝向|

padX=ceil((width−160)/32)，padY=ceil((height−144)/32)，均上限31。这是16px逻辑格的两侧取整，不是逐像素激活。
原生尺寸关闭这些替换。游戏活动对象13槽不扩容；展示数组256项不是256个游戏 AI。
支持更大画布不代表所有远处 NPC 都能激活；超过游戏槽位/扩围上限仍有缺失可能。

## 6. 失败案例与已验证修复

- 只扩 VRAM：横向走动会见旧地图列 → 读取完整地图，而非信任环形 VRAM 缓存。
- 扩围 NPC 后从相反边缘出现：8位坐标 wrap → 地图坐标解包+限制远处对象向 OAM 发布。
- 离屏 NPC 抖动：软件相机偏移比显示寄存器提前 → OAM 已发布姿态优先；未发布对象由地图目标位置、步长、剩余 ticks 重建。
- 朝向离屏重置 → 按对象身份/记录初始坐标/当前地图记忆并在初始化读取点恢复，不把同槽不同对象混为一人。
- 白线/一帧边框消失 → 第一条显示行锁定地图有效性/1300B块/对象列表；过渡期沿用同场景连贯快照，不逐行重新判定。
- 跨地图海/树林填充跳变 → 稳定世界图谱与空间归属，不用当前地图 border 填所有空白。
- 邻图 NPC 到原始屏边界消失 → 在前端复制后的原始区域做预览前景，保护原始玩家/NPC；不要在原 PPU 内插精灵。
- 相邻对象突然出现 → 可见性条件解析+邻图静态预览；未知条件保守退让。

必须保留回归：不同宽高、奇数边距、长距离行走、NPC卸载重进、跨连接、窗口/菜单/战斗、昼夜/星期/事件、变量精灵、原屏边缘玩家遮挡。

## 7. 性能和内存：不要照搬桌面结论

此前 WSL 同一静止场景、音频 dummy、隐藏软件 SDL、每组5轮×3000计量帧：160×144约0.250ms/帧，200×150初版约0.453ms；第一轮去冗余优化约0.413对0.265ms，约+56%。
这些是当时版本/主机进程 CPU 时间；不是 AC6956C8 指标，不是本次模块重构后的逐项 profile，也不是普遍开销。不要写“200×150只多30%性能”或“还能几千FPS所以板上没问题”。

像素增加30.2%；板上2bpp帧缓冲从5760增到7500B，仅多1740B。CPU模拟、原PPU、音频、面板转换/传输、地图/NPC展示应分别计量。
当前默认展示还可能增加真实 NPC AI 与 ROM 缺页；不只增加像素循环。

64位 WSL 编译实测（MCU ABI须重新 sizeof/链接map）：

|配置|适配状态 sizeof|绘制 parts 最坏局部数组|
|---|---:|---:|
|256对象 / 64地图 / 16缓存|10992B|12288B|
|28对象 / 4地图 / 无缓存|2736B|1344B|

后者只是资源裁剪编译验证，不保证原有所有远处邻图/稳定填充表现。运行时关功能不自动释放结构体字段；真正减 RAM 必须调整编译容量，状态结构只保留单份。
排序目前仍使用 libc qsort，嵌入式如无 libc/调用开销过高，应替换为经验证的有界排序或预计算行段表；不要直接拷贝12KB栈数组上板。

AC6956C8 已查配置：240MHz，2bpp存储，SD页缓存，现有原生CPU快速取指，以及每帧 emulate/flush/wait/lag 计量。
现有核心有本地优化，不能用桌面 peanut_gb.h 整份覆盖它。保留快速读取/内存访问/音频路径，仅接窄回调。
项目记录中的《金》滚屏1200帧约59.465FPS已很接近原生59.7275，不意味着一定有可用余量。

建议先以地形-only作最低成本基线，再逐项打开当前NPC绘制、生命周期、连接地图、稳定填充、邻图预览。每一步同存档/同输入记录平均、p95/max帧时、SD缺页/等待、音频欠载、栈高水位、链接RAM。
如超预算应报告具体功能成本，让用户选择组合；不能悄悄跳帧、降低音频或改变PPU来冒充满帧。

## 8. 新游戏与 FC 后端的接手步骤

新游戏：确认平台/版本/hash → 比较原始VRAM与屏外错误 → 找相机/完整地图/解压器 → 只做地形并和原屏逐像素对照 → 分析对象生命周期/坐标/图形 → 判断是否需要运行时补丁 → 加连接/事件条件 → 加真实场景负例与资源预算。
每个版本建立独立描述/实现与原字节断言；只对精确指纹启用。优先展示-only，游戏逻辑补丁显式选择。
可复用同引擎后端，但地区/修订的地址和PC语义必须重新验证。

FC：复用 gx_viewport，新增独立 NES 状态/PPU背景后端，正确处理 nametable mirroring、attribute quadrant、CHR-ROM/CHR-RAM/bank、细滚动、分屏与 mapper IRQ、8x8/8x16精灵。
只读 PPU peek 不得触发寄存器读副作用或改变 mapper latch/IRQ。不能把 GB 的 256×256背景/WRAM布局套过去。
PPU nametable 仍可能过期，完整世界仍需逐游戏后端。不要扩硬件扫描线，不放大OAM容量，不取消原生sprite限制；额外展示只能在合成层进行。

## 9. 交付与验收

模块补丁可单独用；Peanut核心/SDL补丁只是一条已验证端口。导出工具锁定Git基线并生成可核验SHA256与说明，禁止把ROM/用户存档打包。
在干净临时检出按序 git apply --check/apply，然后运行无ROM测试、指定外部ROM的测试、Peanut原回归。补丁成功应用不等于游戏正确，编译成功不等于板上60FPS。
保存原始文件hash/存档hash；测试不得写用户原存档。需要SDL时隐藏或1:1窗口，编译/测试均在WSL进行。
